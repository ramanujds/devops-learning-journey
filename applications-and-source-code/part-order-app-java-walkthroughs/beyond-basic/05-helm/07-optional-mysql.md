# Step 7 — Optional MySQL: Conditionals in Templates

> [Back to index](README.md) · Previous: [Step 6](06-order-templates.md) · Next: [Step 8 — Overlays and Notes](08-overlays-and-notes.md)

## Goal

Add the MySQL objects from walkthrough 04 to the chart behind one switch, `mysql.enabled`, so the same templates produce the H2 stack or the MySQL stack.

## Why this matters

Until now the chart is only the dev stack. The prod stack differs in two ways:
**extra objects** (Secret, init ConfigMap, headless Service, StatefulSet) and
**extra lines inside existing objects** (the MySQL connection settings in the
ConfigMaps, and an `initContainer` plus a password `env` in the Deployments). A
Helm `if` handles both:

- Wrap a whole file in `{{- if .Values.mysql.enabled }}` ... `{{- end }}` and the object disappears when the switch is off.
- Wrap a few lines the same way and only those lines disappear.

An `if` is true for any value except `false`, `0`, an empty string, an empty list/map, or `null`. That is why `existingSecret: ""` means "not set" and why `and .Values.mysql.enabled (not .Values.mysql.existingSecret)` reads naturally.

There is a design weakness to name honestly. The chart has **two** values that
must agree: `springProfile` (`dev` or `prod`) and `mysql.enabled`. Nothing
enforces it. A `prod` profile with MySQL switched off renders cleanly, installs
cleanly, and produces Pods that crash trying to connect to a database that does
not exist. The two overlays in Step 8 set both together, which is the only safeguard; exercise 4 adds a real one.

## 1. Two more helpers

Append to `templates/_helpers.tpl`:

```gotmpl
{{- define "part-order-app.mysqlName" -}}
{{- printf "%s-mysql" (include "part-order-app.fullname" .) -}}
{{- end -}}

{{- define "part-order-app.mysqlSecretName" -}}
{{- if .Values.mysql.existingSecret -}}
{{- .Values.mysql.existingSecret -}}
{{- else -}}
{{- include "part-order-app.mysqlName" . -}}
{{- end -}}
{{- end -}}
```

`mysqlSecretName` is the fork: use the user's `existingSecret` if given, otherwise the chart's own Secret name. Every consumer calls this helper, so they all follow whichever applies.

## 2. The MySQL values

Append to `values.yaml`:

```yaml
# MySQL is only deployed/used when springProfile: prod. See values-prod.yaml.
mysql:
  enabled: false
  image: mysql:8.0
  imagePullPolicy: IfNotPresent

  # Name of a pre-existing Secret with the same keys as `auth` below
  # (MYSQL_ROOT_PASSWORD, INVENTORY_DB_PASSWORD, ORDER_DB_PASSWORD).
  # Leave empty to have the chart generate one from `auth`.
  existingSecret: ""

  # Plaintext dev-safe placeholders only. For a real environment, override
  # via --set or a values file generated by a secret manager (Sealed
  # Secrets, External Secrets, Vault, etc.) - never commit real credentials.
  auth:
    rootPassword: dev-root-pw
    inventoryDbPassword: dev-inventory-pw
    orderDbPassword: dev-order-pw

  inventoryDatabase: part_inventory_db
  orderDatabase: part_order_db
  inventoryUser: inventory_app
  orderUser: order_app

  persistence:
    size: 2Gi
    storageClassName: ""

  resources:
    requests:
      cpu: 250m
      memory: 512Mi
    limits:
      cpu: "1"
      memory: 1Gi

  readinessProbe:
    initialDelaySeconds: 20
    periodSeconds: 10
    timeoutSeconds: 5
  livenessProbe:
    initialDelaySeconds: 40
    periodSeconds: 20
    timeoutSeconds: 5
```

The whole block sits under `mysql:`, with `enabled: false` first, so the default install is still the dev stack. The `auth` passwords are the same dev-safe placeholders as walkthrough 04's Secret; the comment says what to do with real ones.

## 3. Conditional lines in the ConfigMaps

Append to the **end** of `templates/part-inventory-service/configmap.yaml`:

```yaml
  {{- if .Values.mysql.enabled }}
  MYSQL_HOST: {{ include "part-order-app.mysqlName" . | quote }}
  MYSQL_PORT: "3306"
  MYSQL_DATABASE: {{ .Values.mysql.inventoryDatabase | quote }}
  MYSQL_USER: {{ .Values.mysql.inventoryUser | quote }}
  {{- end }}
```

and to the end of `templates/part-order-service/configmap.yaml`:

```yaml
  {{- if .Values.mysql.enabled }}
  MYSQL_HOST: {{ include "part-order-app.mysqlName" . | quote }}
  MYSQL_PORT: "3306"
  MYSQL_DATABASE: {{ .Values.mysql.orderDatabase | quote }}
  MYSQL_USER: {{ .Values.mysql.orderUser | quote }}
  {{- end }}
```

These are the `MYSQL_*` keys the `prod` profile reads. The only differences between the two are the database and user, which now come from values.

## 4. Conditional lines in the Deployments

In **both** Deployments, insert this block directly under the Pod `spec:`, before `containers:`:

```yaml
      {{- if .Values.mysql.enabled }}
      initContainers:
        - name: wait-for-mysql
          image: busybox:1.36
          command:
            - sh
            - -c
            - until nc -z {{ include "part-order-app.mysqlName" . }} 3306; do echo waiting for mysql; sleep 2; done
      {{- end }}
```

and this one inside the container, directly after the `envFrom:` block (inventory shown; the order service uses `ORDER_DB_PASSWORD` and its comment names the inventory service's password):

```yaml
          {{- if .Values.mysql.enabled }}
          env:
            # pulled individually (not envFrom the whole secret) so the app
            # pod never sees MYSQL_ROOT_PASSWORD or the order service's password
            - name: MYSQL_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: {{ include "part-order-app.mysqlSecretName" . }}
                  key: INVENTORY_DB_PASSWORD
          {{- end }}
```

The `wait-for-mysql` initContainer and the single-key `secretKeyRef` are exactly what you wrote by hand in walkthrough 04, now appearing only when MySQL is on. Both use helpers, so the host name and Secret name follow the release.

## 5. The four MySQL templates

Create these in `templates/mysql/`. Each is the walkthrough 04 manifest with names from helpers and values from `mysql.*`.

`secret.yaml`: skipped when `existingSecret` is set, so you can bring your own:

```yaml
{{- if and .Values.mysql.enabled (not .Values.mysql.existingSecret) }}
# Plaintext for local/dev-with-mysql use only. For a real environment, generate
# this with a secret manager (Sealed Secrets, External Secrets, Vault, etc.)
# instead of committing credentials to git - point mysql.existingSecret at it
# and this template is skipped.
apiVersion: v1
kind: Secret
metadata:
  name: {{ include "part-order-app.mysqlName" . }}
  namespace: {{ .Release.Namespace }}
  labels:
    {{- include "part-order-app.labels" . | nindent 4 }}
    app.kubernetes.io/component: mysql
type: Opaque
stringData:
  MYSQL_ROOT_PASSWORD: {{ .Values.mysql.auth.rootPassword | quote }}
  INVENTORY_DB_PASSWORD: {{ .Values.mysql.auth.inventoryDbPassword | quote }}
  ORDER_DB_PASSWORD: {{ .Values.mysql.auth.orderDbPassword | quote }}
{{- end }}
```

`init-configmap.yaml`: database and user names are now values, but the `${...}` password references stay as shell variables (Helm leaves single-brace text alone):

```yaml
{{- if .Values.mysql.enabled }}
# Runs once, only when the StatefulSet's PVC is first initialized (the
# official mysql image only executes /docker-entrypoint-initdb.d/* against an
# empty datadir). Creates one database + one scoped user per service, so
# part-inventory-service and part-order-service can share this MySQL instance
# without either one being able to touch the other's tables.
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ include "part-order-app.mysqlName" . }}-init-scripts
  namespace: {{ .Release.Namespace }}
  labels:
    {{- include "part-order-app.labels" . | nindent 4 }}
    app.kubernetes.io/component: mysql
data:
  init-users.sh: |
    #!/bin/bash
    set -e

    mysql -uroot -p"${MYSQL_ROOT_PASSWORD}" <<-EOSQL
        CREATE DATABASE IF NOT EXISTS {{ .Values.mysql.inventoryDatabase }};
        CREATE DATABASE IF NOT EXISTS {{ .Values.mysql.orderDatabase }};

        CREATE USER IF NOT EXISTS '{{ .Values.mysql.inventoryUser }}'@'%' IDENTIFIED BY '${INVENTORY_DB_PASSWORD}';
        GRANT ALL PRIVILEGES ON {{ .Values.mysql.inventoryDatabase }}.* TO '{{ .Values.mysql.inventoryUser }}'@'%';

        CREATE USER IF NOT EXISTS '{{ .Values.mysql.orderUser }}'@'%' IDENTIFIED BY '${ORDER_DB_PASSWORD}';
        GRANT ALL PRIVILEGES ON {{ .Values.mysql.orderDatabase }}.* TO '{{ .Values.mysql.orderUser }}'@'%';

        FLUSH PRIVILEGES;
    EOSQL
{{- end }}
```

`service.yaml`:

```yaml
{{- if .Values.mysql.enabled }}
apiVersion: v1
kind: Service
metadata:
  name: {{ include "part-order-app.mysqlName" . }}
  namespace: {{ .Release.Namespace }}
  labels:
    {{- include "part-order-app.labels" . | nindent 4 }}
    app.kubernetes.io/component: mysql
spec:
  # headless: gives the StatefulSet pod a stable DNS name, no load-balancing
  # needed since there's a single MySQL instance
  clusterIP: None
  selector:
    {{- include "part-order-app.selectorLabels" . | nindent 4 }}
    app.kubernetes.io/component: mysql
  ports:
    - name: mysql
      port: 3306
      targetPort: 3306
{{- end }}
```

`statefulset.yaml`: the probes, resources, size and optional storage class all come from values:

```yaml
{{- if .Values.mysql.enabled }}
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: {{ include "part-order-app.mysqlName" . }}
  namespace: {{ .Release.Namespace }}
  labels:
    {{- include "part-order-app.labels" . | nindent 4 }}
    app.kubernetes.io/component: mysql
spec:
  serviceName: {{ include "part-order-app.mysqlName" . }}
  replicas: 1
  selector:
    matchLabels:
      {{- include "part-order-app.selectorLabels" . | nindent 6 }}
      app.kubernetes.io/component: mysql
  template:
    metadata:
      labels:
        {{- include "part-order-app.selectorLabels" . | nindent 8 }}
        app.kubernetes.io/component: mysql
    spec:
      containers:
        - name: mysql
          image: {{ .Values.mysql.image }}
          imagePullPolicy: {{ .Values.mysql.imagePullPolicy }}
          ports:
            - name: mysql
              containerPort: 3306
          envFrom:
            - secretRef:
                name: {{ include "part-order-app.mysqlSecretName" . }}
          volumeMounts:
            - name: data
              mountPath: /var/lib/mysql
            - name: init-scripts
              mountPath: /docker-entrypoint-initdb.d
          readinessProbe:
            exec:
              command: ["sh", "-c", "mysqladmin ping -h127.0.0.1 -uroot -p\"$MYSQL_ROOT_PASSWORD\""]
            initialDelaySeconds: {{ .Values.mysql.readinessProbe.initialDelaySeconds }}
            periodSeconds: {{ .Values.mysql.readinessProbe.periodSeconds }}
            timeoutSeconds: {{ .Values.mysql.readinessProbe.timeoutSeconds }}
          livenessProbe:
            exec:
              command: ["sh", "-c", "mysqladmin ping -h127.0.0.1 -uroot -p\"$MYSQL_ROOT_PASSWORD\""]
            initialDelaySeconds: {{ .Values.mysql.livenessProbe.initialDelaySeconds }}
            periodSeconds: {{ .Values.mysql.livenessProbe.periodSeconds }}
            timeoutSeconds: {{ .Values.mysql.livenessProbe.timeoutSeconds }}
          resources:
            {{- toYaml .Values.mysql.resources | nindent 12 }}
      volumes:
        - name: init-scripts
          configMap:
            name: {{ include "part-order-app.mysqlName" . }}-init-scripts
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        {{- if .Values.mysql.persistence.storageClassName }}
        storageClassName: {{ .Values.mysql.persistence.storageClassName }}
        {{- end }}
        resources:
          requests:
            storage: {{ .Values.mysql.persistence.size }}
{{- end }}
```

## Try it

Same chart, two shapes:

```bash
cd ~/helm-lab/part-order-app
helm lint . --set mysql.enabled=true --set springProfile=prod
helm template x . | grep -c '^kind:'
helm template x . --set mysql.enabled=true --set springProfile=prod | grep -c '^kind:'
helm template x . | grep -c wait-for-mysql
helm template x . --set mysql.enabled=true --set springProfile=prod | grep -c wait-for-mysql
```

Expected: `6`, then `10`, then `0`, then `2` (one initContainer per Deployment). Look at what the switch added:

```bash
helm template x . --set mysql.enabled=true --set springProfile=prod | grep -E "^kind:" | sort | uniq -c
helm template x . --set mysql.enabled=true --set springProfile=prod --show-only templates/part-inventory-service/configmap.yaml | grep -E "MYSQL|PROFILES"
```

Expected: 3 ConfigMaps, 2 Deployments, 1 Secret, 3 Services, 1 StatefulSet; and `MYSQL_HOST: "x-part-order-app-mysql"`, `MYSQL_DATABASE: "part_inventory_db"`, `MYSQL_USER: "inventory_app"`.

Now bring your own Secret:

```bash
helm template x . --set mysql.enabled=true --set mysql.existingSecret=my-secret | grep -c "kind: Secret"
helm template x . --set mysql.enabled=true --set mysql.existingSecret=my-secret | grep -B1 -A2 "secretKeyRef" | grep name
helm template x . --set mysql.enabled=true --set mysql.existingSecret=my-secret --show-only templates/mysql/secret.yaml
```

Expected: `0` Secrets, both Deployments' `secretKeyRef` pointing at `my-secret` (the StatefulSet's `secretRef` does too), and an error `could not find template templates/mysql/secret.yaml in chart`, because the template rendered to nothing.

Finally the weakness from earlier. Render the inconsistent combination and read it:

```bash
helm template x . --set springProfile=prod | grep -E "PROFILES|MYSQL" | sort | uniq -c
```

Expected: `SPRING_PROFILES_ACTIVE: "prod"` and no `MYSQL_*` lines at all. It is valid YAML and a broken application.

## Common mistakes

| Symptom | Cause | Fix |
| --- | --- | --- |
| Blank lines or merged lines around a conditional | `{{ if }}` without the `-` trim | use `{{- if ... }}` and `{{- end }}` on their own lines |
| `unexpected EOF` / `unexpected {{end}}` | `if` without a matching `end` | count them per file; `helm template` names the file |
| Pods crash with `Unknown database` or connection refused | `springProfile: prod` but `mysql.enabled: false`, or the reverse | change both together; Step 8's overlays do |
| `${INVENTORY_DB_PASSWORD}` shows blank in the MySQL init script | wrote `{{ ... }}` where a shell variable was meant | keep the shell form `${...}`; only Helm values use `{{ }}` |
| Secret keys not found by Pods | `existingSecret` missing `MYSQL_ROOT_PASSWORD`, `INVENTORY_DB_PASSWORD` or `ORDER_DB_PASSWORD` | the Secret needs exactly those three keys |
| MySQL password change has no effect on an existing install | the password is set only when the volume is first initialised | see walkthrough 04, Step 4 |
